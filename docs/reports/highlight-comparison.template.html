How to read these numbers

We compared the original saved picks with one fixed final run across all six available October 2 halls. We used the same menu items and the same preliminary checklist for both. A check can accept one of several suitable alternatives; the 24 checks are not a count of every main on every menu.

  • Original selections met 12 of 24 checks, or 50%. Refined selections met 21, or 87.5%. The increase is 37.5 percentage points on this checklist. Calling the model “87.5% accurate” would be misleading.
  • The old limit was four highlights per meal. You asked for up to five. The selections grew from 61 to 77 items, so we cannot credit the full gain to prompt changes alone.
  • The checklist was drafted by the assistant. You have not approved it as the correct answer. The refinement loop also saw these menus, so October 2 is not an unseen test.
  • Hall totals have different denominators and are small. Frank's one check, for example, cannot establish that its entire list is perfect.
  • A later McConnell repeat met five of six checks, versus four here. We keep the fixed six-hall run in the main chart so the score does not combine each hall's best attempt.
  • There are no saved actual October 3 and October 4 menu results in this report. The original versus refined labels describe selector versions, not those two calendar days.
  • Oldenborg had no usable saved menu for October 2. Frank only had lunch; Collins had an empty continental breakfast service. The comparison covers the available data.

The selector changes include clearer definitions of mains and sides, soft station guidance for each hall, a fifth available slot, and item IDs that are unique across a hall's meals. The generating model remains Groq GPT-OSS 120B with low reasoning effort. The API changes are local and have not been deployed.
